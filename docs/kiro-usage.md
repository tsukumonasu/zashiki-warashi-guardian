2026-11-20 | spec `cloud-judgement` | Full spec (requirements, design, tasks) and the cloud implementation, executed task by task from `tasks.md` with sub-agents (one task per sub-agent run, a checkpoint task after each group, property-based tests as required tasks). **Design review:** Kiro reviewed the draft design against the AWS documentation and listed 21 corrections (C1 to C21) in `design.md`. Examples: Nova Micro is not in-Region in Tokyo, so Nova Lite is the default; Claude Haiku 4.5 in Tokyo needs the `jp.` profile and a Marketplace agreement; Polly neural voices ignore SSML `pitch`; `status.offline` carries the connect-time `ts`, so the cloud uses arrival time; HTTP API throttling is best effort, so rate limits use DynamoDB counters. **AWS checks through the `aws-docs` MCP server** (each cited in the "Verified AWS facts" table of `design.md`): Tokyo (`ap-northeast-1`) availability and prices for Rekognition, Polly, Bedrock and the other services; IAM resource types in the Service Authorization Reference (`SearchFacesByImage` takes a `collection` ARN, `DetectFaces` has no resource type and uses `*`); Rekognition request limits and rates; Polly voices, `pcm` output format and the 3,000-character limit; Bedrock model ids and lifecycle; the IoT Core 128 KB publish limit, which sets the 90,000-byte JPEG cap in `docs/schema.md`; DynamoDB TTL and transaction shapes. A local `cdk` check confirmed `NODEJS_24_X` and `S3BucketOrigin.withOriginAccessControl` (`cloud/test/cdk-constants.test.ts`). **Property-based tests:** fast-check properties cover verdict totality, thresholds, monotonicity and failure handling, envelope round trip, cross-language fixtures, authorization, redaction, TTL, rate limiting, WAV header, sanitizer, lines and the snapshot size bound. Reviewer isolation: a reviewer gets illustrations and redacted records only, and the snapshot URL signer is the only role with `s3:GetObject` on `snapshots/*`; the signer is the owner's decision (A5). **Defects that tests found:** (1) the ingest core had no way to undo its dedup claim, so a redelivery after a failed write was dropped as a duplicate; a `releaseClaim` method was added to the state port, the DynamoDB adapter (conditional on the claim's own `claimedAt`) and the fake. (2) `POST /simulate` audio was stored under a key prefix that did not match the one read back and signed, found by a test of the generated speech path; the prefix was corrected. (3) `FakeRepo.listEncounters` returned wrong pages when a cursor was used, so pagination tests passed against a broken fake; the fake was fixed so the tests exercise the real contract. (4) After a failed write the redelivered message skipped the meta update because the first attempt had already marked it seen; the redelivery now completes the missing write. **Still unverified:** latency of Lambda, IoT rules, Rekognition, Bedrock and Polly in Tokyo; the real shape of the `cognito:groups` claim at an HTTP API Lambda (code accepts an array or a string); billed amounts; `python3-paho-mqtt` on the Raspberry Pi archive (only the Debian page was checked); no deployment, real Bedrock or Polly call, or e-mail delivery was run by Kiro, so integration tests stay opt-in. **Left to the owner:** seed the demo face collection with consented portraits and `samples/manifest.json` (O1); confirm the SNS e-mail subscription within 48 hours (O2); put notification and budget e-mail addresses in the git-ignored `cdk.context.json`; enable the Bedrock model; run the latency harness and fill in the measured values (tasks 24.1, 24.2); confirm the paho-mqtt version on the doll (O8) | Decided the reviewer-isolation design (signer function, A5) and the Bedrock model choice; kept the owner steps out of the automated tasks | `.kiro/specs/cloud-judgement/{requirements,design,tasks}.md`, `cloud/test/ingest-core.test.ts`, `cloud/test/cdk-constants.test.ts`, `cloud/test/fakes.ts`
